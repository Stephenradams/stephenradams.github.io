# Allowing AI development to become why development

Everywhere we look there are people vibe coding, using amazing tools to build complete applications in a matter of minutes or hours. 
Want a full featured mobile app, done. Want a complete new website, here you go. It's easy there's no need to worry about anything the AI tooling will do it all for you. 

Well that's the vision that both AI companies and nearly every other video on YouTube will have us believe and in a way it's true you can get these tools to generate a decent application just from describing what you want. It is pretty amazing.

What I've found from using these tools and working on the applications that these tools generate is that there is an issue that is not being addressed or considered when spitting out these applications. That is how are these going to be maintained if no one really knows what's been 

## An application is never done

Throughout my career I've worked with a many companies, and the one thing that has been consistent in each project is that an application is never done, its released, but it's never done/complete. There's always a new feature or a UI improvement or user feedback that needs to be addressed as soon as an application is released the work starts all over again. 

There is always something else to do and if you have an application that has been built with an architecture that makes it hard to update parts of the application or making a small change to one part leads to changes to several unrelated sections of the app, where all the code is so tightly coupled together one small text change leads to a PR of 20 files all needing changes (I've seen this many times) then there are serious problems.

## Using AI to fix issues caused by AI

You could decided that in order to fix issues in your fully generated AI application that you'll simply using AI to fix this problems or make the small text changes that involve a 20 file PR, but every time you are asking AI to do anything for you it's more of your tokens you are using. 

So you'll eventually you'll be paying the AI companies to use their AI tools to fix issues caused by there AI tools. That will soon become very expensive not only financially but also time wise.  
Each change means more time waiting for the AI to review the recent changes, understand the problem, come up with a solution and then implement the solution. If at the start the applications architecture was planned and built with maintainability in mind this small text change that now has turned into a 20 file PR that has cost 1000's in tokens could have been a small 1 file change, quickly made by one developer. 

## Developers will be here to support you when needed 

Now if you have used AI to build you the first version of your application that's great, but are you prepared to support, maintain and update this application? Do you know how it's been built? Or where to look if there is an urgent bug that needs fixing?  

We've all seen these YouTube videos where someone is saying 'I built this app without knowing a line of code' that's amazing for them, but are they a large enterprise organisation with a business critical application that has to service all the companies clients and if the application breaks will it lose them money, probably not. 

If you are a large enterprise company or a company building an application that is a core part of your business and you have people working on the application who have just 'vibe' coded it well good luck, don't forget people like me who can help when you need someone to jump in and help improve the maintainability of the application. When you are ready we will be here for you.

## Using AI can be helpful

I'm not against using AI tools. I use them daily as part of my workflow, but I'm finding the more I use them the more I feel they should be used as tools to support the development I do and not replace everything I do, but as a developer I would say that.

The main concern I have is that I see many people believe that just using AI tooling will allow them to build amazing applications that will work perfectly forever and they as a non-developer will never have to speak to or use a developer again. They forget about maintenance or future proofing or making updates or having to upgrade their application and if they decide that a small change is something they want to do themselves they will find that the code of their AI generate application will lead them to wonder why things have been developed that way.
